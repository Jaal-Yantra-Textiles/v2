# SURVEY: Design → Order Paths (jyt backend)

> Grounded behaviour document for every path by which a design becomes an order or draft order.
> All claims cite full repo-relative paths, verified against source read on 2026-09-09.

## 1. Purpose

This area turns designs into purchasable commerce objects. There are two fundamentally different shapes: (a) **variant-less custom line items** — a design is priced by an estimator (or manual override) and placed on a cart as a custom-priced line item carrying only `metadata.design_id`, and (b) **variant-backed lines** — a real product/variant is minted from the design (`design_product_variant` link) and ordinary variant-keyed machinery (quote → cart → order) is reused. A third family turns designs into **production work-orders** (unified orders) rather than sales orders.

- **Duplicate guard on #1/#2**: `createDesignDraftOrder` refuses if ANY of the design_ids already has a `design_line_item` link (DUPLICATE_ERROR, "Remove them from existing carts first") — `apps/backend/src/api/admin/designs/draft-order/lib.ts:44-61`.
- **Pricing on #1/#2**: per design, `price_overrides[design_id]` wins (confidence "manual", tagged `source_currency` = `override_currency`); otherwise `estimateDesignCostWorkflow`; a `null` `total_estimated` **throws** rather than zero-pricing (#1564) — `apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:60-108`. FX conversion to the target currency happens in `convert-estimate-currency-step` (`apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:124-198`).
- **Cart setup on #1/#2**: region matched by currency (fallback first region), store default sales channel (fallback any), customer email only when a customer exists (guard against `filters: { id: undefined }` matching everything) — `apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:218-285`.
- **#5 payment treatment**: a payment collection is ALWAYS created; `prepaid` → `markPaymentCollectionAsPaid` (payment_status=captured); `cod` → left not_paid for later Shiprocket-remittance reconciliation — `apps/backend/src/workflows/designs/convert-design-order.ts:232-256`.
- **#5 idempotency**: refuses if `cart.completed_at` or `cart.metadata.converted_order_id` is set (`apps/backend/src/workflows/designs/convert-design-order.ts:143-153`); on success stamps both on the cart, removing it from abandoned-cart recovery (#443) (`apps/backend/src/workflows/designs/convert-design-order.ts:262-277`).
- **#6 quote-line resolution**: a design line is resolved to the variant it is sold through — `design_product_variant` (1:1, wins) else `product_design` catalogue variants; ambiguous (>1 candidate) or no product → refused unless a variant is minted — `apps/backend/src/modules/partner-quote/lib/design-lines.ts:154-240`, `apps/backend/src/modules/partner-quote/lib/design-lines.ts:469-527`.

### 4.2 Q2 — Does the line item carry a real `variant_id`?

- **Paths #1/#2 (admin draft order): NO.** The line items are custom: `title`, `unit_price`, `is_custom_price: true`, `requires_shipping: false`, `quantity: 1`, `metadata: { design_id, cost_confidence, ... }` — no `variant_id`, no `product_id` (`apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:288-311`). **No product needs to exist**; the price comes from the estimator or `price_overrides` (`apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:60-108`).
- **Path #3 (store design checkout): NO.** Same custom-item shape (`apps/backend/src/api/store/custom/designs/[id]/checkout/route.ts:124-143`). No product required; the route's own docblock says admin approval "later creates the real product/variant" (`apps/backend/src/api/store/custom/designs/[id]/checkout/route.ts:18`).
- **Path #4 (order from store checkout): NO at creation.** The order items inherit the cart's variant-less items — confirmed by the subscriber skipping them for run creation because they have no `product_id` (`apps/backend/src/subscribers/order-placed.ts:109`). A variant can be attached **retroactively** by #7's backfill, which updates order line items matching `metadata.design_id` and `!item.variant_id` (`apps/backend/src/workflows/designs/create-product-from-design.ts:507-514`).
- **Path #5 (admin convert): NO, deliberately.** Order items are title-only (`title`, `quantity`, `unit_price`, `metadata` incl. `source_cart_line_item_id`) so the PLACED subscriber's production-run branch is skipped — converting a customer design order must NOT spawn a production work-order (`apps/backend/src/workflows/designs/convert-design-order.ts:38-41`, `apps/backend/src/workflows/designs/convert-design-order.ts:169-179`).
- **Path #6 (B2B quote): YES.** `acceptQuoteWorkflow`'s cart items are `{ variant_id: l.variant_id, quantity }` (`apps/backend/src/workflows/partner-quote/accept-quote.ts:433-436`). **This path REQUIRES a product/variant to exist**: either an existing one (resolved via `design_product_variant` or `product_design`, `apps/backend/src/modules/partner-quote/lib/design-lines.ts:164-240`) or one minted on demand by `ensureDesignQuoteVariantWorkflow` → `createProductFromDesignWorkflow` (`apps/backend/src/workflows/partner-quote/ensure-design-quote-variant.ts:244-259`). The design→order association on this path is via the variant (`design_product_variant`), not via `design_order`.
- **Paths #8/#9 (work-orders): NO.** Work-order items are built per production run with design/run pointers in metadata (`apps/backend/src/workflows/production-runs/dual-write-unified-run-order.ts:485-486`, `apps/backend/src/workflows/production-runs/dual-write-unified-run-order.ts:255-259`); they are not variant-backed sales lines.

### 4.3 Q3 — Duplicate paths

1. **`POST /admin/customers/:id/design-order` ≡ `POST /admin/designs/draft-order` — literal duplicates.** Both call the same `createDesignDraftOrder` (`apps/backend/src/api/admin/designs/draft-order/lib.ts:36`); the customer route passes the param id, the designs route passes `body.customer_id?.trim() || null` (`apps/backend/src/api/admin/designs/draft-order/route.ts:22`, `apps/backend/src/api/admin/customers/[id]/design-order/route.ts:22-23`). Identical end state (cart + `design_line_item` links). **`/admin/designs/draft-order` is the more general form** — the customer is optional (#1817: most designs carry no customer link), while the customer route remains "the addressable form for 'this buyer's order'" (`apps/backend/src/api/admin/designs/draft-order/route.ts:8-13`). They cannot drift by construction ("both go through the same function", `apps/backend/src/api/admin/designs/draft-order/route.ts:12-13`).
2. **Store checkout (#4) vs admin convert (#5) — parallel implementations of "design cart → real order".** Same end state (a real order containing the design cart's items, with `design_order` links), different code: checkout is customer-driven through core cart completion, with `design_order` written by the `order.placed` subscriber's `linkDesignsToOrder` (`apps/backend/src/subscribers/order-placed.ts:169`); convert is the admin-side shortcut for carts the customer never checked out (#404, `apps/backend/src/workflows/designs/convert-design-order.ts:18-24`), which must link designs **explicitly** because its cartless draft has no `order_cart` link for the subscriber's traversal (`apps/backend/src/workflows/designs/convert-design-order.ts:41-43`). Checkout is the more complete path (real payment provider, address collection, natural PLACED side effects); convert replicates the linking and payment marking itself (system-provider `markPaymentCollectionAsPaid` or COD-unpaid, `apps/backend/src/workflows/designs/convert-design-order.ts:232-256`) and suppresses the customer email with `no_notification: true` (`apps/backend/src/workflows/designs/convert-design-order.ts:198`).
3. **`POST /admin/orders/:id/design/produce` (#8) vs `POST /admin/designs/produce` (#9) — both produce ONE collated kind=design work-order via the same collation core** (`apps/backend/src/workflows/designs/create-runs-for-design-order.ts:113`, `apps/backend/src/workflows/designs/produce-designs-as-work-order.ts:347`). They are complements rather than strict duplicates: #8 fans runs out of an existing commissioning order's line items and is idempotent (skips line items that already have a run, keyed on `order_line_item_id` — `apps/backend/src/workflows/designs/create-runs-for-design-order.ts:52-63`); #9 works straight from designs with no order and "there is no group key to be idempotent against (no order), so every call creates a fresh batch" (`apps/backend/src/workflows/designs/produce-designs-as-work-order.ts:56-57`). #9 is the more complete producer (per-design template dispatch, #1263 — `apps/backend/src/workflows/designs/produce-designs-as-work-order.ts:244-257`; partner-open collation, #1597 — `apps/backend/src/workflows/designs/produce-designs-as-work-order.ts:321-344`); #8 is the only one that ties runs to sales-order line items.

Not duplicates but one shared primitive: `createProductFromDesignWorkflow` is invoked from the approve route (`apps/backend/src/api/admin/designs/[id]/approve/route.ts:80`), the quote mint (`apps/backend/src/workflows/partner-quote/ensure-design-quote-variant.ts:244`), and the production-run approval path (`apps/backend/src/workflows/production-runs/approve-run-output.ts:395`).

## 5. Gotchas / invariants

- **`requires_shipping` MUST stay `false` on the CART for variant-less design items** or `completeCartWorkflow`'s `validateShippingStep` makes checkout unsatisfiable (#1195) — `apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:294-300`, `apps/backend/src/api/store/custom/designs/[id]/checkout/route.ts:129-132`, `apps/backend/src/lib/requires-shipping.ts:14-20`. Repair happens at order.placed, and only for items whose product carries a shipping profile (`apps/backend/src/subscribers/order-placed.ts:75-101`, `apps/backend/src/lib/requires-shipping.ts:46-55`).
- **Unpriceable designs hard-fail everywhere** (null `total_estimated`, #1564): admin draft creation (`apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:95-99`), store checkout (`apps/backend/src/api/store/custom/designs/[id]/checkout/route.ts:94-99`), quote minting (`apps/backend/src/workflows/partner-quote/ensure-design-quote-variant.ts:210-224`).
- **`order.cart_id` is not a column** — order↔cart is the `order_cart` link module; the original #379 bug was subscriber code selecting a non-existent column (`apps/backend/src/workflows/designs/link-designs-to-order.ts:20-22`).
- **`linkDesignsToOrder` is idempotent** (skips existing (design, order) pairs) and shared by the subscriber and the backfill script so the traversal cannot drift (`apps/backend/src/workflows/designs/link-designs-to-order.ts:73-92`, `apps/backend/src/scripts/backfill-design-order-links.ts:52-56`).
- **Convert's title-only items are load-bearing**: they make the PLACED subscriber skip production-run creation for customer design orders (`apps/backend/src/workflows/designs/convert-design-order.ts:38-41`); producing a design order is a separate explicit admin step (#8) (`apps/backend/src/workflows/designs/create-runs-for-design-order.ts:14-19`).
- **`design_product_variant` is 1:1 and `link.create` is not idempotent** — a second mint leaves a design resolving to two variants, making it unquotable (`apps/backend/src/workflows/partner-quote/ensure-design-quote-variant.ts:126-131`).
- **The quote path writes no `design_order`/`design_line_item` links** — quote carts hold variant items, so the subscriber's `linkDesignsToOrder` traversal finds nothing; the design association lives on the variant (`design_product_variant`), which `resolveLineItemDesignId` uses for run creation (`apps/backend/src/lib/resolve-line-item-production.ts:27-39`).
- **Duplicate-cart guard is global, not per-customer**: any existing `design_line_item` link for a design blocks a new admin draft order for it (`apps/backend/src/api/admin/designs/draft-order/lib.ts:44-61`).
- **FX**: estimates are denominated in the store default currency; manual overrides carry `override_currency`; conversion uses the Frankfurter API with 1-hour in-memory cache (`apps/backend/src/workflows/designs/create-draft-order-from-designs.ts:115-198`, `apps/backend/src/api/store/custom/designs/[id]/checkout/route.ts:103-122`).
- **Convert stamps `completed_at` + `converted_order_id` last**, so a mid-failure retry isn't blocked, and the cart leaves the abandoned-cart flow (#443) (`apps/backend/src/workflows/designs/convert-design-order.ts:262-277`).
- **Work-orders are excluded from retail views** by the `order↔production_run` link (the kind=design discriminator) and `metadata.collated_design_order` (`apps/backend/src/workflows/production-runs/dual-write-unified-run-order.ts:268-278`, `apps/backend/src/workflows/production-runs/dual-write-unified-run-order.ts:495-505`).
